* すぐ終了

## STEP 1：ログと時間だけ作る

**作るもの**

* 開始時刻
* `timestamp X message` を出す関数
* mutex でログを守る

**分かること**

* 「時間付きログ」の意味
* なぜprintfを守る必要があるか

👉 まだ coder なし

---

## STEP 2：coder を1人だけ動かす

**作るもの**

* coderスレッド 1人
* compile → debug → refactor を順に表示
* usleep で時間を再現

**分かること**

* pthread_create / join
* スレッドが「勝手に動く」感覚

👉 共有資源なし

---

## STEP 3：coder を複数に増やす（資源なし）

**作るもの**

* coder を N人に増やす
* 全員が同時にログを出す

**分かること**

* 同時実行
* ログが混ざる問題 → mutex の必要性

---

## STEP 4：dongle を1本だけ作る

**作るもの**

* dongle 1個
* mutex で守る
* 1人しか取れない

**分かること**

* 「共有資源」を守るとはどういうことか

---

## STEP 5：dongle を2本にして「2本必要」にする

**作るもの**

* dongle を2つ
* 両方取れたら compile

**分かること**

* デッドロックが自然に起きる
* なぜ順序が必要か

👉 この時点で一度ハマるのが正解

---

## STEP 6：最低限のデッドロック回避

**作るもの**

**分かること**

* 「ルール1つで止まらなくなる」感覚

---

## STEP 7：cooldown を足す

**作るもの**

* dongleに「次に使える時間」
* すぐ取れない状態を作る

**分かること**

* mutexだけでは足りない
* 「時間」も状態になる

---

## STEP 8：待つ仕組み（cond）

**作るもの**

* 取れない時に待つ
* 条件が変わったら起きる

**分かること**

* busy wait と cond_wait の違い
* 「寝て待つ」感覚

## STEP 9：scheduler（FIFO）だけ実装

# 登場人物（まずこれだけ押さえる）

## 1️⃣ main（司令塔）

* 世界を作る
* スレッドを起動する
* 最後に全員を回収する

👉 **開始と終了の責任者**

---

## 2️⃣ coder（作業員）

* dongle を取りたい
* 仕事（compile）をする
* 終わったら報告する

👉 **実際に働く人たち**

---

## 3️⃣ dongle（共有資源）

* 同時に使えない
* cooldown がある
* 順番や締切で管理される

👉 **限られた道具**

---

## 4️⃣ scheduler（STEP9/10 のロジック）

* queue（FIFO / EDF）を見て
* 「次に進める人」を決める

👉 **選別役（命令はしない）**

---

## 5️⃣ monitor（監視役）

* 定期的に全体を見る
* 異常（deadline miss）を検知
* 正常終了も検知
* 終了フラグを立てる

👉 **止める判断をする唯一の存在**

---

# 全体の流れ（大枠）

```
main
 ├─ monitor 起動
 ├─ coder 起動（複数）
 │    ├─ dongle を取りたい
 │    ├─ 待つ / 進む
 │    ├─ compile
 │    └─ done
 ├─ monitor が終了を判断
 └─ main が全員 join
```

# 時系列で追う（ここが一番大事）

## 🟢 フェーズ1：起動

### main の仕事

1. `shared` を初期化

   * stop = 0
   * finished_coders = 0
2. dongle / mutex / cond / queue を初期化
3. **monitor を起動**
4. **coder を起動**

👉 この時点で世界が動き始める

---

## 🟡 フェーズ2：coder が並ぶ

### coder_routine 開始

```c
coder X wants to compile
```

### take_dongle に入ると

* 自分の **deadline** を決める
* queue にエントリーする

👉 ここで scheduler（EDF）が効き始める

---

## 🟡 フェーズ3：待つ・起きる・選ばれる

### 待っている coder は

```c
pthread_cond_timedwait(...)
```

* CPU を使わず寝ている
* 起こされる理由は2つ：

  * dongle が解放された
  * 時間（timedwait）

### 起きたら必ずやること

```c
while (条件がダメ)
    また寝る
```

条件は：

1. 誰も使ってない
2. cooldown 終了
3. **EDF で自分が最優先**

👉 **選ばれるのではなく、自分で条件を満たす**

---

## 🟢 フェーズ4：compile

条件を満たした coder だけが：

```c
took dongle
compiling
```

* dongle を占有
* 他の coder は待つ

---

## 🟡 フェーズ5：解放と通知

compile が終わると：

```c
released dongle
```

内部で起きてること：

* in_use = 0
* cooldown 設定
* `pthread_cond_broadcast`

👉 **「状況変わったよ！」と全員に通知**

---

## 🔴 フェーズ6：monitor の仕事（並行）

monitor はずっと横でこれを繰り返す：

### ① 異常チェック

```c
deadline < now ?
```

→ あったら

* stop = 1
* 全員起こす

### ② 正常終了チェック

```c
finished_coders == num_coders ?
```

→ だったら

* stop = 1
* 全員起こす

👉 **monitor だけが stop を立てる**

---

## 🟢 フェーズ7：終了伝播

### stop = 1 になると

#### coder 側

* while を抜ける
* 途中でも撤退
* return

#### monitor 側

* 自分も while を抜ける
* return

---

## 🟢 フェーズ8：回収

### main がやること

* coder 全員 join
* monitor join
* mutex / cond destroy
* free
* program finished

👉 **世界がきれいに終わる**

---

# 超重要な設計ポイントまとめ

## ① 命令しない

* 「お前行け」は言わない
* 条件だけを用意する

## ② 起こすけど、選ばない

* cond は全員起こす
* 条件でふるいにかける

## ③ 止める役は1人

* monitor だけが stop を立てる
* coder は従うだけ

## ④ 終了はイベント

* 正常終了も「イベント」
* 異常終了と同じくらい設計が必要
